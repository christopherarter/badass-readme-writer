# Design evidence from current OSS READMEs

Reviewed 2026-09-30. These are observations about current repository READMEs, not templates or enduring facts about the products. Revisit the links when using them as current examples.

- [Immich](https://github.com/immich-app/immich/blob/main/README.md): a large product screenshot near the top makes the UI recognizable before the feature table. Its long locale and feature lists also show why strong visual proof does not excuse a dense opening.
- [Hono](https://github.com/honojs/hono/blob/main/README.md): brief personality, a precise framework description, a tiny route example, and a one-command quick start create a fast understanding-to-action path. Its many badges are a useful reminder to preserve the example while trimming introductory noise.
- [Coolify](https://github.com/coollabsio/coolify/blob/main/README.md): says what can be deployed, on whose servers, and why that ownership matters; then offers a supported install route. This demonstrates practical positioning rather than an abstract feature inventory.
- [Astro](https://github.com/withastro/astro/blob/main/README.md): a compact product explanation, `npm create` path, browser starter, docs, help, and welcoming contribution route make navigation effortless. A mature project can let its docs carry the deeper detail.
- [Bun](https://github.com/oven-sh/bun/blob/main/README.md): defines the toolkit and shows small command examples quickly. Its extensive later links illustrate why a README can still become a reference index if scope is not controlled.
- [Supabase](https://github.com/supabase/supabase/blob/master/README.md): the Postgres/Firebase mental model and ecosystem explanation help readers orient around a platform made of multiple tools. That model should be borrowed only when a comparison is accurate.
- [Trigger.dev](https://github.com/triggerdotdev/trigger.dev/blob/main/README.md): leads with what developers can build and the operational outcomes of durable tasks, then includes a code example. Its unusually long feature list shows the need to curate outcomes for the root README.
- [n8n](https://github.com/n8n-io/n8n/blob/master/README.md): early banner and screenshot, plain-language product story, and an immediately visible Docker route connect the UI to trying it. The cloud/self-hosting distinction also makes the next path clear.
- [uv](https://github.com/astral-sh/uv/blob/main/README.md): a concrete one-line category, visual benchmark, and specific capabilities offer proof for a performance-oriented CLI. Benchmark numbers in another project require independently verified methods and context.
- [Excalidraw](https://github.com/excalidraw/excalidraw/blob/master/README.md): a theme-aware cover and linked editor establish the visual character of a UI product. Its separate [package README](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/README.md) also demonstrates that an embeddable library needs a different first path than the hosted app.

The shared principle is to place the project's best evidence near its claim, give one low-friction route to value, and move exhaustive detail to maintained docs. The differences are just as useful: a screenshot suits Immich or n8n; an executable snippet suits Hono; a mental model helps Supabase; a measured proof point can help uv. The skill should choose based on the actual repository and audience.
